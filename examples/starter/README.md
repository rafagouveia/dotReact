# DotReact starter

## Repository setup

The scaffold is ready to become a repository but deliberately does not run
`git init`. It includes `.gitignore`, `.gitattributes`, `.editorconfig`,
`.dockerignore`, pinned Node/.NET expectations, shared build rules, VS Code recommendations
and a GitHub Actions quality/container workflow. Run `npm install` before the
first commit and commit the generated `package-lock.json` for reproducible CI.

This app uses ASP.NET Core for backend page loaders and React for SSR and browser
hydration.

## Workspace modes

Generated projects open in **focus mode**: VS Code shows application code and
official extension points, while generated contracts, renderer bootstraps,
deployment assets and pinned runtime sources stay out of the normal Explorer and
search results. Nothing is deleted. Reveal the advanced infrastructure only when
you need to customize deployment or low-level tooling, then return to the focused
view:

```powershell
dotreact workspace status
dotreact workspace reveal
dotreact workspace focus
```

The visible `Server/Program.cs` is intentionally small. Add application-owned
services or middleware around `AddDotReactApplication()`,
`UseDotReactApplication()` and `MapDotReactApplication()`; renderer supervision, Redis, images, security,
observability, discovery and production defaults remain framework-owned.

## Coding agents and Codex Cloud

`AGENTS.md` is the mandatory entry point for coding agents. It requires the
complete `docs/ai` manual to be read in order before changing code. The manual
covers the product profile, runtime ownership, DRX/routing, SSR/streaming,
hydration, C# ↔ React interpolation, Server Actions, security, SSG/ISR, cache,
production and verified implementation recipes.
It also defines the required SOLID feature layout and the modular CSS/SSR
first-paint contract.

```powershell
npm install
npm run dev
```

Projects created during the pre-release vendor the CLI too, so project-local
commands work without a global installation:

```powershell
npm exec -- dotreact doctor
npm exec -- dotreact generate page catalog/[slug]
npm exec -- dotreact check
```

Open `http://127.0.0.1:5080`.

Key files:

- `public/` is the single source for fonts, icons and public images. The
  framework serves it in development and Vite copies it into production.
- `app/fonts.ts` is the optional typed declaration point for local fonts through
  `@dotreact/font`; mark non-critical faces with `preload: false` and never duplicate generated CSS.
- `@dotreact/script` declares validated external scripts with `beforeInteractive`,
  `afterInteractive` or `lazyOnload`; inline JavaScript is intentionally unsupported.
- `app/page.drx` and `app/page.server.cs` are the React view and C# loader for `/`.
- `app/products/[id]/` co-locates the dynamic view, loader, props and prerender policy.
- `app/streaming/` demonstrates co-located props and streaming SSR.
- Route boundaries are supplied by the framework; optional `app/**/not-found.drx`, `error.drx` and `loading.drx` files override the nearest fallback.
- `app/layout.drx` wraps every page; nested directories can add their own
  `layout.drx`, composed from root to leaf. Layouts receive the current C# page
  props and URL through `DotReactLayoutProps`.
- `Server/Actions/IncrementDemo/IncrementDemoAction.cs` is an explicitly exposed C# server
  action with authorization metadata and antiforgery protection.
- `src/contracts.ts`, `src/actions.ts` and `src/backend-manifest.json` are
  generated from the compiled C# application. Run `npm run generate` to update
  them or `npm run check:contracts` to detect drift.
- `docs/ai/07-SOLID-FEATURES.md` defines the feature-first C# dependency rule,
  thin Presentation adapters, focused use cases and CSS ownership.

The client and SSR entries are generated by the framework. Do not create
`entry-client.tsx` or `entry-server.tsx`. Production keeps route JavaScript split,
generates a private route-asset manifest and injects fingerprinted global/route
CSS plus initial module preloads into the SSR head. Applications do not declare
bundle filenames, and SSR never paints before the selected route CSS is available.

Routes included in the starter:

| URL | Behavior |
| --- | --- |
| `/` | React SSR with props loaded by C# and browser hydration. |
| `/products/{id}` | Dynamic page with prerender/ISR enabled. |
| `/streaming` | React streaming SSR with an immediate Suspense fallback. |

Use `/products/7` for a normal product, `/products/404` for the not-found
result, `/products/500` for the error boundary and `/products/302` for a
redirect. Although `id` is converted to `int` by the loader, the inferred route
does not include an ASP.NET route constraint. Use the two-argument
`DotReactPage` overload when a constraint such as `{id:int}` is required. Page
modules may export `metadata` or a typed metadata resolver; DotReact serializes
only supported title/meta/link fields into the document head.

Folders such as `(catalog)` organize routes without changing their URL. Folders
beginning with `_` are private and ignored by route discovery. Under `app/`, only
`page.drx` becomes a route, so local helpers can live safely in `_components`.

## Streaming SSR

The starter enables protocol-v2 streaming with `EnableStreaming = true`.
`/streaming` sends the document shell and Suspense fallback before the delayed
server segment is ready. The per-request CSP nonce is forwarded to React's
streaming renderer. Renderer failures are classified as `before-shell` until a
start frame is emitted and `after-shell` from that point onward, so the ASP.NET
host can choose the correct response behavior without pretending that an
already-started response can be replaced.

The classic protocol-v1 `render` entry remains available for hosts that do not
negotiate streaming.

## Prerender and ISR

The product loader declares:

```csharp
[DotReactPrerender(2, StaleWhileRevalidateSeconds = 30, Tags = ["products"])]
```

Generated pages are fresh for 2 seconds and may be served stale for another 30
seconds while regeneration runs. `ProductStaticPaths` supplies product IDs 1,
2 and 3 for build-time generation; other valid IDs are generated on demand.
The cache key includes the configured build ID, so a new deployment does not
reuse HTML produced by an incompatible frontend bundle. The `products` tag can
be used by server-action revalidation to invalidate the related entries.

Set `DOTREACT_BUILD_ID` to an immutable deployment or commit identifier. The
starter also recognizes `CONTAINER_APP_REVISION` and `WEBSITE_DEPLOYMENT_ID`;
otherwise it uses `development` locally and `local-production` in production.
Production deployments should provide a stable, unique value for every release.

The starter associates `*.drx` with TypeScript React in VS Code. In another
editor, associate `.drx` with TSX to get the same highlighting and language
features. `npm run typecheck` additionally checks `.drx` semantics, page props,
layout signatures and drift against `src/backend-manifest.json`. DRX does not
execute C# inside JSX; typed props and server actions are the language boundary.

The `vendor/` directory is a pinned pre-release runtime snapshot. VS Code hides
it from normal browsing and search, and application code must never edit it.
It will become pinned package dependencies once the public packages are
available.

The one-argument page attribute derives routing from the DRX module ID:

```csharp
[DotReactPage("products/[id]/page")] // /products/{id}
```

Generated projects include a production Dockerfile for Azure App Service or Azure
Container Apps. ASP.NET exposes port 8080 and supervises the private Node SSR
renderer; use `/_health/live` and `/_health/ready` for platform probes.

Production enables a strict CSP/security-header baseline and per-instance Server
Action rate limiting. The generated HTML and action responses are `no-store`;
fingerprinted assets are immutable while stable asset names are revalidated.

The host registers OpenTelemetry for ASP.NET Core, HTTP, DotReact renderer,
Server Actions and browser CLS/INP/LCP/TTFB. Browser samples use bounded labels
and continue the SSR trace through W3C trace context. Set
`OTEL_EXPORTER_OTLP_ENDPOINT` to send traces and metrics to an OTLP collector;
without it, no exporter connection is attempted. Advanced hosts may set
`EnableBrowserVitals = false` without changing application views.

For an action that can be retried safely, add `[DotReactIdempotent]`, send a
stable `idempotencyKey` from the generated client call, and return local paths
through `DotReactActionResult.Success(value, revalidatePaths)` when consumers
need a revalidation signal. The default store is bounded and process-local.

Before committing a C# ↔ TypeScript boundary change, regenerate and validate
the contracts, then run the normal quality gates:

```powershell
npm run generate
npm run check:contracts
npm run typecheck
npm test
npm run build
npm audit --audit-level=high
```

`generate` compiles the C# server before writing `src/contracts.ts`,
`src/actions.ts` and `src/backend-manifest.json`. Commit those files together
with the loader or action change that produced them.
